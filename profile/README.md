# posture-sec

We audit the configuration that public chains already expose, because almost nobody reads it.

One rule shapes everything here: a tool that inspects your accounts must not be able to hurt them. Every project in this org is read-only and secret-free by construction, not by convention.

Gauge looks at accounts on the chain, Airlock looks at the code and CI that publish to it, the fixtures repository holds the account-shaped JSON both of them are meant to test against, and stellar-posture-watch runs Gauge on a schedule and files what it finds into one issue nobody remembered to ask about. Neither tool has been pointed at the corpus yet. The Action has written its issue: #6 in its own repository, opened by a scheduled run and kept current by the one after it, carrying a finding that came from Gauge at a pinned commit. What stays open there is somebody else's repository doing the same. Those are the repositories' own open gates rather than finished ones. They share working conventions and no code.

The third project exists because of a method problem. A rule written against a hand-typed fixture passes until the first real account disagrees with the invention, and the fix for that is not a bigger test suite inside either tool: it is captures with provenance something can re-check, kept in a repository whose only job is keeping them honest. Two of the four above arrived on 2026-11-02, and they arrived differently. Airlock moved here after the GitHub account that published it was suspended, so its repository, its history and its documentation were recovered rather than restarted. The fixtures corpus was written here.

The fourth was written here on 2026-11-04, and it exists because a tool nobody runs is not a control. An audit that only lives in a CLI drifts from the day it is installed; the same read has to arrive on a schedule, in the repository that owns the account, with its findings somewhere a person looks.

## How the work runs

- **The roadmap is the contract.** Each repository carries a `ROADMAP.md`, and CI refuses to merge a change that does not update it in the same pull request. Task IDs, a changelog row and a progress table move together.
- **Claims are traceable or marked.** Every number in a README, on the docs site and on this page is read from the code or from a named run against a named network and ledger. What has not been verified says so.
- **Findings are posture, never safety.** Nothing here will call an account secure. The chain shows signers, thresholds and flags; a read-only tool cannot know your intent, so it reports what it read and how far it looked.
- **Failure is loud.** An unreachable endpoint, an oversized or malformed response, an unknown config key, a rule that panics: all of them exit nonzero. Exit 0 means the run completed and every rule it evaluated agreed with the policy.

## Reporting a problem

Each repository states its own scope and disclosure path: [Gauge's SECURITY.md](https://github.com/posture-sec/guage/blob/main/SECURITY.md), [Airlock's SECURITY.md](https://github.com/posture-sec/airlock/blob/main/SECURITY.md) and [the corpus's SECURITY.md](https://github.com/posture-sec/stellar-account-fixtures/blob/main/SECURITY.md) and [the Action's SECURITY.md](https://github.com/posture-sec/stellar-posture-watch/blob/main/SECURITY.md). In the corpus the reportable thing is a false claim about provenance rather than an account: bytes that do not match their sidecar, seed-shaped material anywhere in the tree, or a validator that exits 0 on a corpus it should refuse. Read the status section of whichever repository you are reporting against first: it tells you whether what you found is a bug or a limitation that is already written down.
