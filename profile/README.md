# posture-sec

We audit the configuration that public chains already expose, because almost nobody reads it.

One rule shapes everything here: a tool that inspects your accounts must not be able to hurt them. Every project in this org is read-only and secret-free by construction, not by convention.

## Projects

| Project | What it does | State |
| --- | --- | --- |
| [Gauge](https://github.com/posture-sec/guage) | Reads a Stellar account's signers, thresholds, flags and home domain from Horizon, compares them with a policy file you declare, and exits nonzero when the two disagree. Go CLI, binary `stellar-gauge`. | Unaudited, functional alpha. [Documentation site](https://posture-sec.github.io/guage/) live since 2026-11-02. |
| [Airlock](https://github.com/posture-sec/airlock) | Scans a Stellar or Soroban *repository* for supply-chain compromise and release-integrity gaps: what a workflow can reach, what a manifest declares, what a package's lifecycle scripts do. Python CLI, binary `airlock`, zero runtime dependencies. | Unaudited, functional alpha with no Action yet. `v0.0.1` is a pre-release, not a version to depend on. [Documentation site](https://posture-sec.github.io/airlock/) live since 2026-11-02. |
| [Stellar account fixtures](https://github.com/posture-sec/stellar-account-fixtures) | Six mainnet account reads captured from Horizon, each beside a sidecar recording the source URL, the capture time, the ledger, the Horizon version that served it and the digest of the bytes next to it, plus the validator that recomputes every one of those claims and the capture tool that refuses a bad checksum, a wrong passphrase, a redirect and anything seed-shaped. It holds no rule, no severity and no verdict about whether an account is well configured. | Public since 2026-11-02. Six captures, 95 tests, no tag and no documentation site. The eight shape labels with no capture are printed in its README rather than papered over. |

Gauge looks at accounts on the chain, Airlock looks at the code and CI that publish to it, and the fixtures repository holds the account-shaped JSON both of them test against. They share working conventions and no code.

The third project exists because of a method problem. A rule written against a hand-typed fixture passes until the first real account disagrees with the invention, and the fix for that is not a bigger test suite inside either tool: it is captures with provenance something can re-check, kept in a repository whose only job is keeping them honest. Two of these three arrived on 2026-11-02, and they arrived differently. Airlock moved here after the GitHub account that published it was suspended, so its repository, its history and its documentation were recovered rather than restarted. The fixtures corpus was written here.

## How the work runs

- **The roadmap is the contract.** Each repository carries a `ROADMAP.md`, and CI refuses to merge a change that does not update it in the same pull request. Task IDs, a changelog row and a progress table move together.
- **Claims are traceable or marked.** Every number in a README, on the docs site and on this page is read from the code or from a named run against a named network and ledger. What has not been verified says so.
- **Findings are posture, never safety.** Nothing here will call an account secure. The chain shows signers, thresholds and flags; a read-only tool cannot know your intent, so it reports what it read and how far it looked.
- **Failure is loud.** An unreachable endpoint, an oversized or malformed response, an unknown config key, a rule that panics: all of them exit nonzero. Exit 0 means the run completed and every rule it evaluated agreed with the policy.

## Reporting a problem

Each repository states its own scope and disclosure path: [Gauge's SECURITY.md](https://github.com/posture-sec/guage/blob/main/SECURITY.md), [Airlock's SECURITY.md](https://github.com/posture-sec/airlock/blob/main/SECURITY.md) and [the corpus's SECURITY.md](https://github.com/posture-sec/stellar-account-fixtures/blob/main/SECURITY.md). In the corpus the reportable thing is a false claim about provenance rather than an account: bytes that do not match their sidecar, seed-shaped material anywhere in the tree, or a validator that exits 0 on a corpus it should refuse. Read the status section of whichever repository you are reporting against first: it tells you whether what you found is a bug or a limitation that is already written down.
